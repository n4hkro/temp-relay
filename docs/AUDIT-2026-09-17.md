# Temp Relay 1.29.1 — yoxlama və düzəlişlər

Son 10–15 saniyəlik doldurma gecikməsi ayrıca real extension sınağı ilə təkrarlandı və düzəldildi: [ölçmələr və səbəblər](LATENCY-2026-09-17.md). Eyni yavaş iframe ssenarisində keçid+doldurma 12 249 ms-dən 261 ms-ə düşdü. Sonrakı qeydiyyat modalı gecikməsi də ümumi açılış mexanizmində düzəldildi: canlı CMC sınağında açılış+doldurma 2555 ms, qəsdən 2200 ms gecikdirilmiş böyük SPA sınağında 2367 ms oldu.

Məqsəd: müvəqqəti poçt ünvanı ilə qeydiyyatı tamamlamaq, gələn kodu/keçidi düzgün seçmək, sayt hesabının məlumatını ailə domenləri ilə birlikdə təmizləmək və şəxsi proxy-ləri idarə etmək.

## Düzəldilən davranışlar

- **Sessiya:** eyni anda başlayan əmrlər, saxlanma və silinmə sıralanır. Dayandır gecikmiş Başlat əməliyyatının sessiyanı qaytarmasına mane olur və ünvan sorğusunu ləğv edir. Sessiyalar UUID ilə fərqləndirilir. Paralel yeniləmələr bir-birinin sahələrini itirmir.
- **Poçt izləməsi:** köhnə sessiyanın gec cavabı yeni sessiyada kod göstərmir. Eyni məktubun sonradan gələn gövdəsi yenidən təhlil edilir. Ünvanın yaradılmasından əvvəlki tarixli məktublar bir dəqiqə saat fərqi nəzərə alınmaqla atılır. Yenidən göndərilmiş, uyğun aktivasiya məktubu köhnə məktubdan üstün tutulur.
- **Kod və keçid seçimi:** mövzudakı OTP oxunur; mövzu və gövdədə təkrarlanan kod birləşdirilmir. Ana səhifə, abunəlikdən çıxma və məxfilik keçidləri aktivasiya keçidi seçilmir. Keçidin yolu, parametr adı və ya keçid mətni aktivasiya mənası daşımalıdır.
- **Ünvan:** yararsız email cavabları rədd olunur. Ünvan clipboard əməliyyatından əvvəl saxlanır; kopyalama uğursuzluğu qeydiyyatı dayandırmır.
- **emailnator:** müvəqqəti boş gövdə daimi keşlənmir; həddən böyük tarix qutunun oxunmasını dayandırmır. Gövdə keşi ünvan və məktub id-si ilə ayrılır.
- **Formalar:** Send code düyməsi yanındakı email kod xanası sayılmır. Qeydiyyat dialoqu əlaqəsiz email/telefon sahələrindən ayrılır; eyni dialoqdakı ayrı parol bloku da doldurulur. Login paneli signup-a çevriləndə yenidən qiymətləndirilir. Əlaqəsiz formanın razılıq xanasına toxunulmur.
- **Webshare qeydiyyatı:** `current-password` ipucu formanın öz birmənalı qeydiyyat submit-ini üstələmir; deaktiv submit də tanınır. Formanın yaxın qardaş blokundakı şərtlər/məxfilik razılığı tapılır. Əhatə başqa forma və ya əlaqəsiz mətn sahəsinə çatanda genişlənmir. Açılış mərhələsi sahəli formanın submit-ini və onun içindəki mətn elementini basmır. `Sign Up With Email` hesab qeydiyyatı kimi tanınır, kod istəyi ilə qarışmır.
- **Göndərmədən əvvəl yoxlama:** boş, sayt tərəfindən silinmiş/dəyişdirilmiş, etibarsız və ayrılmış sahə göndərməni dayandırır. Tələb olunan naməlum sahə, radio qrupu və işarələnməmiş razılıq da yoxlanılır. Doldurma və göndərmə ayrı yeridilmələr olsa da klikdən əvvəl canlı DOM yenidən yoxlanılır.
- **Sürət:** ünvan yaradılması və formanın açılması paralel başlayır. Hazır forma cavabından sonra əvvəlki 1,2 saniyəlik fasilə yoxdur. Naviqasiya yeni `documentId` və interactive DOM əsasında aşkarlanır; kənar iframe/şəkillərin `complete` hadisəsi və ölmüş açılış skriptinin cavabı gözlənmir. Clipboard və bildiriş də doldurmanı saxlamır. `injectImmediately` hazır sahələri `document_idle` gözləməsindən azad edir; sahə gec yaranarsa mövcud DOM müşahidəsi qalır. [Chrome-un rəsmi scripting sənədi](https://developer.chrome.com/docs/extensions/reference/api/scripting#type-ScriptInjection).
- **Naviqasiya və iframe:** yazma nəzərdə tutulan sayt və onun tanınmış hesab ailəsi ilə məhdudlaşır. Frame origin-ləri əvvəlcə yalnız oxunur, sonra icazəli sənədlərə dəyər ötürülür. Göndərmə doldurulmuş sənədin `documentId`-sinə bağlanır. Azure → Microsoft giriş keçidi saxlanılır.
- **Domen sərhədləri:** qısa əl siyahısı rəsmi Public Suffix List snapshot-ı ilə əvəz edilib. ICANN, şəxsi hostinq, wildcard və istisna qaydaları nəzərə alınır. Azure/Blogspot kimi hostinqlərdə müstəqil saytlar qarışdırılmır. IP, IPv6 və localhost üçün saxta `www` origin-ləri yaradılmır.
- **Təmizləmə:** geniş host icazəsi əlaqəsiz iframe-in saxlancını silməyə səbəb olmur. Cookie sadalanmasında müstəqil hostinq tenant-ları ailənin üst domenindən ayrılır. Tab başqa hosta keçibsə yenilənmir; status yalnız həqiqətən tamamlanan yenilənməni bildirir. Cookie sayı əlçatan/sadalanan cookie-lərə aiddir.
- **Proxy:** siyahı və Chrome parametri ilə bağlı dəyişikliklər sıralanır. Ayrılma köhnə şəbəkə sorğusunu gözləmir. Köhnə qoşulma/bərpa nəticəsi yeni seçimi qaytarmır və silmir. Startup istifadəçinin yeni əmrini üstələmir.
- **Proxy yoxlaması:** Chrome-un effektiv sahibi, sxemi, hostu və portu tətbiqdən sonra və uğur bildirişindən əvvəl yoxlanır. Cavab həqiqi IP olmalıdır. Ləğv və vaxt limiti cavab gövdəsinə də tətbiq edilir. Yanlış/işləməyən, extension-a məxsus parametr buraxılır.
- **Proxy autentifikasiyası:** giriş məlumatı yalnız seçilmiş HTTP/HTTPS proxy-nin uyğun challenger host/port sorğusuna, effektiv parametr bizə aid olduqda verilir. Təkrar cəhdlər məhduddur. Chrome-un dəstəkləmədiyi parollu SOCKS rədd edilir. JSON-da naməlum protokol səssiz HTTP-yə çevrilmir. URL-kodlanmış giriş məlumatı idxal/ixracda qorunur.

## Əlavə imkanlar

- **Poçtu yenidən yoxla:** mövcud ünvanı, parolu və profili saxlayaraq izləməyə yeni vaxt pəncərəsi verir.
- **Daha çox göstər:** proxy siyahısında ilk 120 qeyddən sonrakılar da açılır. Qoşulma xətasından sonra düymə yenidən işlək olur.
- `npm run update:psl` rəsmi domen qaydalarının oflayn snapshot-ını yeniləyir. Runtime zamanı şəbəkədən qayda yüklənmir.
- `node tools/browser-qa.mjs` yalnız localhost-da sınaq paneli və forma açır. Chrome API-ləri saxtadır; real hesab, poçt və proxy parametri dəyişmir.

## Yoxlama və sərhədlər

- Reqressiyalar əvvəl uğursuz testlə göstərilib, sonra düzəlişlə keçib. Son tam yoxlama: `npm run verify` — **870 test, 153 suite, 0 xəta**, təxminən 10 saniyə.
- İndependent forma yoxlamasında tapılmış üç reqressiya — parçalanmış parol bloku, birləşən OTP və auth iframe-i — ayrıca testlərlə düzəldilib. Proxy dəyişiklikləri də ayrıca oxunub, startup yarışı və cavab gövdəsinin ləğvi üçün əlavə testlər yazılıb.
- Agent-browser ilə real Chromium DOM-da email/parol və düzgün razılıq xanası doldurulub, əlaqəsiz newsletter sahəsi boş qalıb, yalnız Send code basılıb. Paneldə retryInbox əmri, 120 → 125 sətir, uğursuz proxy əməliyyatından sonra düymənin açılması və JavaScript xəta siyahısının boşluğu yoxlanıb. Görünüş screenshot ilə baxılıb.
- **Canlı Webshare səhifəsi:** əvvəlki davranış eyni DOM-da təkrarlandı: boş sahələrlə iki submit kliki cəhdi, sonra giriş paneli səhvi. Düzəlişdən sonra açılış `{already:true}`, doldurma `email + password`, razılıq `checked:1`, xəta siyahısı boşdur. Email boşaldılanda və razılıq götürüləndə klik sayı artmır; hazır formada bir klik cəhdi var. Sınağın capture listener-i klik/submit-i saxlayıb: real hesab yaradılmayıb. Son ölçmə hazır səhifədə tanıma **2 ms**, doldurma **130 ms**; bu, səhifə yüklənməsi və poçt provayderi vaxtını əhatə etmir, ümumi sürət zəmanəti deyil.
- Canlı poçt provayderləri, ödənişli proxy və real hesab qeydiyyatı ilə tam uçdan-uca sınaq aparılmayıb. Saytdan asılı forma evristikası hər mümkün sayt üçün zəmanət vermir. Host icazələri və Chrome API-lərinin imkanları təmizləmənin əhatəsini müəyyən edir.
